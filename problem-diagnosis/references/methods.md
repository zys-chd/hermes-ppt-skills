# 分析方法详解

> 按需查阅。SKILL.md 的主表已给出选择依据，这里是每个方法的具体做法。

### 5W2H — 界定问题
What 什么现象 / Where 哪里发生 / When 何时 / Who 涉及谁或哪个批次 / Why 为什么是问题 /
How 多严重 / How much 量化（失效率、损失、频次）

### 人机料法环（4M1E）— 五维排查
人（操作者/班组/技能）、机（设备/工装/产线）、料（物料/批次/供应商）、
法（工艺/参数/流程）、环（温湿度/应力/环境）
**关键提醒**：警惕单维度假象 —— 某维度异常可能只是另一个维度分布不均造成的假关联，
必须做交叉验证（如料×环、料×机）。

### 鱼骨图（因果图）— 发散
按 4M1E 分类列出所有可能原因，每条都要能落到可验证的具体项。

### 5Why — 追根因
从现象连续追问"为什么"，直到找到**可行动**的根本原因。
不要停在"人员疏忽""环境不好"这类不可行动的层面。

### FMEA — 风险预防
失效模式 × 严重度(S) × 频度(O) × 可探测度(D) = RPN，按 RPN 排序优先处理。

### 帕累托 — 抓主要矛盾
按频次/损失排序，找累计 80% 的那几个类别。

### 8D — 系统闭环
D1 小组 → D2 描述问题 → D3 临时遏制 → D4 根因 → D5 永久对策 → D6 验证 → D7 预防 → D8 总结

### 分层/交叉分析 — 数据类问题
先按各维度拆开看（区域/时间/批次/产线），再两两交叉，定位问题集中的子集。

### 故障树分析（FTA）— 复杂系统失效路径
从**顶事件**（最终失效现象）往下逐层分解，用逻辑门连接：
- **与门（AND）**：所有下级事件同时发生才导致上级 → 「料缺陷 × 低温」这类交互
- **或门（OR）**：任一下级事件发生即导致上级 → 多条独立失效路径

**什么时候比 5Why 好**：硬件/系统级问题常有**多条并行失效路径**，5Why 是线性追问
（一条链），会漏掉其他分支；FTA 能同时铺开所有路径，并明确哪些是"必须同时满足"的
组合条件（这正是"料×环交互"这类问题的表达方式）。

**排查清单化**：FTA 的每个底事件（最底层可观测事件）就是一条待验证项，
判据是"该事件是否成立"。

### 控制图 / SPC — 判断过程是否失控
用均值-极差图（X̄-R）、单值移动极差图（I-MR）等，把数据按时间画在控制限内：
- **连续 7 点上升/下降**、**超出 3σ 控制限**、**明显周期性** → 过程异常（特殊原因）
- 数据都在控制限内随机波动 → 属正常波动（普通原因），**别去追**

**核心价值**：回答"这个数据变化是真的异常，还是本来就该这样波动"。很多"不良率上升"
其实是正常波动，SPC 能避免过度反应；反过来也能抓住被人忽略的缓慢漂移。

### DOE / 假设检验 — 验证因素是否真有影响
- **假设检验**：t 检验 / 卡方 / 方差分析（ANOVA），判断两组数据差异是否显著（p<0.05）
- **DOE（实验设计）**：同时考察多个因子及交互作用（如"料×温度"），用最少的试验次数
  找到关键因子组合。常用正交试验、全因子/部分因子设计

**什么时候用**：有数据但不确定差异是真影响还是偶然；或在多个可疑因子中要找出真正起作用的。

### A3 报告 — 一页纸问题解决
把整个问题解决过程压缩到一张 A3 纸上（左半"现状/目标/原因"，右半"对策/计划"）：
背景 → 现状 → 目标 → 原因分析 → 对策 → 实施计划 → 效果确认 → 标准化

**适合**：向上汇报、跨部门沟通。强迫你把逻辑压缩到一页，写不下就说明还没想清楚。
**与 8D 的关系**：A3 是呈现形式，8D 是内容框架，可以"用 A3 格式呈现 8D 内容"。

### KT 法（Kepner-Tregoe）— 结构化问题分析与决策
四个基本流程：
- **状况评估（SA）**：多个问题并发时，先排序（影响/紧迫/趋势）
- **问题分析（PA）**：用"是/不是"矩阵界定问题边界 —— 哪里出现/哪里没出现、
  何时/何时没有、什么对象/什么对象没有，通过差异缩小范围
- **决策分析（DA）**：多方案时用"必须项（Must）+ 期望项（Want加权）"筛选
- **潜在问题分析（PPA）**：预判对策可能带来的新问题及应对

**什么时候用**：问题边界模糊、不知道从哪切；或多个方案要结构化比较。外企/汽车行业常用。
